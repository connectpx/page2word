# Implementation decisions

- The project is a Manifest V3 Chrome extension. Source lives in `src`; `dist`
  is generated by `npm run build` and is not the source of truth.
- The extension includes a built-in editor at `chrome-extension://` so normal
  extraction and Word export need no local server. An optional browser editor
  is served from `http://localhost:5173` so other browser extensions can work
  with the page.
- `scripts/dev-server.mjs` uses Node.js built-ins to serve the prebuilt
  `dist/editor` files. It does not need `npm install` at runtime. The popup
  checks it only when the user requests writing-assistant mode.
- Article content and settings stay in the user's browser: handoff data uses
  Chrome storage, and editor documents, sections, and image assets use local
  IndexedDB. Article text is not sent to an application backend.
- Article HTML is sanitized before display and again before export. The
  original-site-links setting defaults to removing source hyperlinks while
  preserving their text; generated in-document figure and table references
  remain navigable.
- DOCX export preserves supported document structure and embedded captured
  images. Preparation can be cancelled, and document generation runs in a
  worker.
- Formatting defaults and the original-site-links preference are stored in
  Chrome local storage and apply to the editor and exports.
- The built-in extension folder can be shared as an unpacked Chrome extension
  without Node.js. Sharing the optional browser-editor mode also requires
  `dist/editor`, `scripts/dev-server.mjs`, and Node.js on the recipient's
  computer.
